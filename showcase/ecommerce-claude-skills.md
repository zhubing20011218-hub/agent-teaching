# 复刻：电商分析 skill

> **原作品：** [mardab96/ecommerce-claude-skills](https://github.com/mardab96/ecommerce-claude-skills)（MIT），20 个电商分析 skill
> **做出来是什么样：** 你自己的一个“退货原因分析”skill：把后台导出的退货表交给它，就得到一份分清“证据”和“猜测”、按影响排好序、写明谁来决定的分析报告
> **难度：** ⭐⭐ · 大约 40 分钟
>
> 下面的提示词是我们读了原作的 `returns-reason-miner-ecommerce/SKILL.md`（退货原因分析）和 `references/output-standard.md`（所有 skill 共用的输出标准）之后反推的，**不是作者的原话**，也没有实际运行过。
>
> **这个作品最值得学的是做法：** 每个 skill 结构都一样（什么时候用 → 需要什么数据 → 分析前先确认 → 分析步骤 → 输出格式 → 不要做的事），金额计算交给脚本，不让 AI 心算。

## 准备

1. 新建文件夹 `ai-练习/电商skill`
2. DSH 选它当工作区，权限「工作区内修改」

## 第 1 步：先造一份练习数据

```text
生成一份假的退货数据 returns.csv（不要用任何真实客户信息），60 行，列：
日期, 订单号, 商品编码, 商品名, 规格, 数量, 退货原因, 买家备注
商品 5 种（保温杯、帆布包、蓝牙耳机、T恤、台灯），退货原因从这些里选：尺码不合适、颜色和图片不一样、质量问题、不想要了、发错货、物流太慢。
故意让“T恤”的“尺码不合适”和“台灯”的“颜色和图片不一样”特别多。
再生成 sales.csv：同期每个商品的销量。
```

## 第 2 步：写 skill

```text
在 .dsh/skills/returns-analyzer/ 下写一个 skill，SKILL.md 用下面的结构：
1. 什么时候用：用户想知道商品为什么被退、哪些退货可以避免
2. 需要的数据：最少要退货表（商品、日期、数量、原因）；最好还有同期销量、商品页截图
3. 分析前先确认：退货政策和统计时间段；原因是买家选的、客服填的还是自由文字；先把同义的原因合并
4. 分析步骤：按商品、规格、原因、时间分组；有销量就算退货率；分出“可以避免的”（尺码、描述不符、质量、发错）和“正常的”（不想要了）
5. 输出格式：每条发现都写——证据（来自哪个表）/ 推测、影响多大、把握多大、改起来费不费劲、建议谁来决定；缺数据就明说缺什么
6. 不要做的事：不直接改店铺设置；不编造“改了能提升多少转化”这种数字
所有计算写一个 Python 脚本 scripts/returns_stats.py 来做，SKILL.md 里写明调用方法。
```

✅ **检查：** 文件夹里有 `SKILL.md` 和 `scripts/returns_stats.py`；DSH 输入框打 `/returns` 能看到它。
🔧 **不对的话：** `SKILL.md 开头的头部信息里 name 要写成 returns-analyzer（只能小写字母和短横线），请改正。`

## 第 3 步：用练习数据测试

```text
用 returns-analyzer 分析 returns.csv 和 sales.csv。
```

✅ **检查：** 报告里排第一、第二的应该是“T恤 尺码不合适”和“台灯 颜色和图片不一样”（这是第 1 步故意埋的）；每条都写了证据和把握程度。
🔧 **不对的话：**
- 退货率算错 → `T恤的退货率算错了，请把脚本的计算过程打印出来给我看，再修正。`
- 写了没依据的数字 → `报告里“改了尺码表能减少 40% 退货”没有依据，请删掉，改成“建议观察下个月的数据”。`

## 第 4 步：照着再做一个

结构跑通了，换个场景再做一个，比如评论分析：

```text
照 returns-analyzer 的结构，再写一个 review-miner skill：从商品评论里找出买家最在意的点和最常见的顾虑。用同样的输出格式。
```
