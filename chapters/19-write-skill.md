# 第 19 章 写你自己的第一个 Skill

> **学完这一章，你能：**
> - 判断什么事值得写成 skill
> - 从零写出一个 skill（不用写代码）
> - 写好 `description`，让 AI 该用时用、不该用时不用
> - 测试、修改，并分享给别人
>
> **前置：** 第 15–18 章

## 1. 为什么要学这个

别人写的 skill 再好，也不知道**你的**习惯：你公司的配色、你喜欢的报告格式、你常犯的错。

前面三章你已经看过三个 skill(`meeting-notes`、`ppt-polish`、`reliable-research`)。你应该发现了：**它们都只是用中文写清楚的“做法”和“规矩”。** 你完全可以自己写。

## 2. 讲解

### 什么事值得写成 skill

一个简单的判断标准：**同一个要求，你已经跟 AI 说了 3 次以上。**

比如：

- 每次做 PPT 都要说“用公司的蓝色、思源黑体、封面放 Logo、最后一页写联系方式”
- 每次写周报都要说“分成完成、进行中、下周计划三部分，每部分不超过 5 条”
- 每次查资料都要说“只看官方网站，给我链接”

### 不适合写成 skill 的

| 情况 | 应该放哪 |
|---|---|
| 每次对话**都要遵守**的规则（比如“永远用中文回答”） | AGENTS.md（第 22 章） |
| AI 本来**没有的能力**（比如连接某个数据库） | MCP 或插件（第 20、21 章） |
| 只用一次的要求 | 直接在对话里说 |

### 写 `description` 的公式

`description` 决定 AI 会不会用你的 skill（第 14 章讲过）。用这个公式写：

> **做什么** + **什么时候用（列出用户可能说的话）** + （可选）**什么时候不用**

例子：

```
description: 按我的个人风格制作或修改 PPT:我的配色、字体、封面和结尾页格式。
  用户说"做 PPT""做个汇报""幻灯片""演示文稿",或者给了 .pptx 文件要修改时使用。
  只是问 PPT 软件怎么操作时不用。需要和 pptx skill 一起用。
```

要点：

- 把用户**真的会说的话**写进去（“做个汇报”“幻灯片”），AI 才能对上
- 写清楚**边界**，防止乱触发
- 一般两三句话就够，不要写成一整页

## 3. 跟着做：写一个“我的 PPT 风格”skill

### 第一步：想清楚你的规矩

拿出纸笔或备忘录，回答这几个问题（写你真实的偏好）：

1. 主色是什么？(比如公司的蓝色 `#1E5AA8`，不知道色号就写“深蓝色”)
2. 用什么字体？
3. 封面放什么？（标题、副标题、你的名字、日期、Logo?）
4. 结尾页放什么？（谢谢？联系方式？总结？）
5. 有什么**一定不要**的？（比如“不要用剪贴画”“不要用动画”）

### 第二步：建文件夹和文件

1. 打开 `~/.dsh/skills/`（第 15 章教过怎么打开）
2. 新建一个文件夹，名字叫 `my-ppt-style`

> [!TIP]
> skill 名字建议用**英文小写字母和短横线**，比如 `my-ppt-style`。避免空格和中文，在各种工具里都不容易出问题。

3. 用 VS Code（第 1 章）新建一个文件，保存到 `my-ppt-style` 文件夹里，文件名 **`SKILL.md`**

### 第三步：写内容

复制下面的模板，**把尖括号 `< >` 里的内容换成你自己的**：

```markdown
---
name: my-ppt-style
description: 按我的个人风格制作或修改 PPT:我的配色、字体、封面和结尾页格式。用户说"做 PPT""做个汇报""幻灯片""演示文稿",或者给了 .pptx 文件要修改时使用。只是问 PPT 软件怎么操作时不用。需要和 pptx skill 一起用。
---

# 我的 PPT 风格

做 PPT 的具体文件操作按 pptx skill 的方法做;版式和风格按下面的规定。

## 配色
- 主色:<深蓝色 #1E5AA8>,用于标题和重点
- 强调色:<橙色 #F28C28>,每页最多用一两处
- 其他文字:深灰色;背景:白色

## 字体
- 中文:<思源黑体>;英文和数字:<Arial>
- 标题 <32> 号,正文 <20> 号,不小于 18 号

## 封面
- 大标题、一行副标题
- 右下角:<我的名字> 和 <日期>
- <左上角放 Logo,文件在 ~/Documents/logo.png>

## 结尾页
- <一句话总结 + 我的邮箱>
- 不要只写"谢谢"

## 一定不要
- <不要动画和切换效果>
- <不要剪贴画、不要 3D 图表>
```

保存。

> [!WARNING]
> 第一行必须是 `---`,`name` 和 `description` 都要有，两段 `---` 要成对。格式错了，DSH 会跳过这个 skill。

### 第四步：测试（三个测试）

和第 15 章一样，做三个测试：

**测试一：AI 自己判断**——新开会话，不提 skill 名字：

```
帮我做一个 5 页的 PPT,主题是"我们小组本月的工作总结",保存为 PPT练习/月度总结.pptx
```

✅ 看到「加载技能」→ `my-ppt-style`(和 `pptx`)，成品符合你的配色、字体、封面、结尾页。

**测试二：手动叫**——`/my-ppt-style` 开头，确认能用。

**测试三：不该用时不用**——问 `PowerPoint 里怎么插入页码?`，不应该加载 `my-ppt-style`。

### 第五步：根据测试结果修改

| 测试结果 | 原因 | 怎么改 |
|---|---|---|
| 该用时没用 | `description` 里没有你说的那种说法 | 把你实际说的话加进 `description` |
| 不该用时乱用 | `description` 范围太宽 | 加一句“……时不用” |
| 用了，但效果不对 | 正文写得不够具体 | 把要求写得更具体：用数字（字号、行数）代替形容词（“大一点”） |
| 用了，但 AI 忽略了某条 | 那条写在太后面，或者和别的要求冲突 | 把重要的放前面；删掉互相矛盾的要求 |

改完保存，**不用重启 DSH**，新开会话再测。

> [!TIP]
> **让 AI 帮你改 skill。** 你可以说："我写了一个 skill 在 ~/.dsh/skills/my-ppt-style/SKILL.md，测试时发现……，帮我改进它的 description 和正文，改之前先给我看修改方案。"

## 4. 练习二：把“靠谱搜索”改成你自己的版本

把第 18 章的 `reliable-research` **复制一份**，改名为 `my-research`，然后按你的需要改，比如：

- 你是做跨境电商的：加上“优先看平台官方的卖家中心、政策公告”
- 你是学生：加上“优先看学术论文、学校图书馆数据库”
- 你只看中文：改成“只给我中文来源；英文来源翻译要点”

记得把 `name` 改成 `my-research`,`description` 也改成符合你的情况。

## 5. 分享你的 skill

skill 就是一个文件夹，分享很简单：

1. 在 GitHub 上新建一个仓库，把 skill 文件夹放进去
2. 加一个 `README.md`，写清楚：这个 skill 干什么、怎么安装、举一个使用例子
3. 加一个 `LICENSE` 文件（许可证）。常用的 **MIT**：别人可以随便用，只要保留你的署名

> [!WARNING]
> 分享前检查：skill 里**有没有你的个人信息**（名字、邮箱、Logo 路径、公司内部信息）？有的话，换成占位符，比如 `<你的名字>`。

## 7. 常见问题

**问：skill 正文写多长合适？**
答：能说清楚就好，一般几十行到两百行。太长 AI 会抓不住重点，也更花钱。很长的参考资料，可以放进 skill 文件夹的另一个文件里(比如 `参考资料.md`)，在正文里写“需要时去读 参考资料.md”。

**问：可以用中文写 skill 吗？**
答：可以。DeepSeek 对中文理解很好。`name` 建议用英文，其他都可以用中文。

**问：skill 里能放图片、模板文件吗？**
答：可以。放进 skill 文件夹，在正文里写清楚文件名和什么时候用，比如“封面背景用同文件夹里的 cover.png”。
