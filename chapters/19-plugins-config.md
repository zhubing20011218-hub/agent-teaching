# 第 19 章 插件和配置文件

> **学完这一章，你能：**
> - 理解 DSH“一切皆插件”是什么意思
> - 在 DSH 里浏览、安装、关闭插件
> - 看懂插件“版本不兼容”的提示，知道该怎么办
> - 安全地修改配置文件
>
> **前置：** 第 18 章（改过一次配置文件）

## 1. 为什么要学这个

DSH 最大的特点是“**一切皆插件**”。社区里已经有很多人做了插件：新皮肤、新功能、新工具……

但插件装多了、装错了，也可能让 DSH 变慢、出错，甚至有安全风险。这一章教你**会装，也会管**。

## 2. 讲解

### “一切皆插件”是什么意思

打个比方：DSH 像一套**乐高**。

- 你看到的界面、AI 用的工具、连接 DeepSeek 的功能、权限审批……**全都是一块块乐高积木**（插件）
- 官方给你拼好了一套默认的样子
- 你可以**加积木**（装插件）、**拆积木**（关掉插件）、**换积木**（换成别人做的版本）

所以 DSH 可以被改造成很多样子，这是它强大的地方；但积木之间也可能“对不上”，这是要小心的地方。

### Skill、MCP、插件，再分清一次

| | 改变了什么 | 难度 | 风险 |
|---|---|---|---|
| Skill | AI **知道的做法** | 低，写文字就行 | 低到中（带脚本的要小心） |
| MCP | AI **能用的工具** | 中，改一段配置 | 中 |
| 插件 | **DSH 本身**（界面、功能、工具、行为） | 中到高 | **较高**：插件是在 DSH 内部运行的程序，权限很大 |

**能用 skill 解决的，就别装插件。**

### 版本兼容：积木对不上

DSH 更新很快，插件是别人做的，不一定跟得上。每个插件都会声明“我适用于哪些版本的 DSH”。DSH 启动时会检查，**不兼容的插件会被跳过**，并提示类似：

```
dsh: skipping profile bundle "某某插件": Error: Plugin 某某插件@0.2.0 is incompatible with dsh 0.2.2-rc.1 ...
Running it may cause crashes or data loss.
```

意思是：“某某插件和当前 DSH 版本不兼容，强行运行可能崩溃或丢数据，所以跳过了。”

**遇到这种提示怎么办：**

1. **首选**：去插件页面看看有没有新版本，更新插件
2. **其次**：不用它了，就卸载
3. **不推荐**：DSH 允许你“明确接受风险”强行运行某个版本（叫“精确版本豁免”）。新手**不要这样做**

## 3. 跟着做：浏览和管理插件

### 看已经装了什么

1. 打开「**插件**」页面
2. 「**已安装**」标签页列出所有插件，每个都有开关

**新手的原则：不认识的官方插件，不要随便关。** 有些是 DSH 正常运行必需的。

### 从插件索引安装（实验功能）

DSH 有一个实验功能，可以从“插件索引”（一个插件清单）里浏览和安装插件：

1. 「插件」页面 → 在「**实验性插件**」下找到「**自定义插件索引**」，打开开关
2. 「已安装」旁边会出现「**发现**」标签页
3. 点「**添加索引源**」，输入一个插件索引的网址(**必须是 `https://` 开头**)
4. 浏览插件，点「**安装**」，会弹出确认框，**显示这个版本从哪里来**（npm 包或 GitHub 仓库）
5. 确认来源没问题，再点确认安装

> [!WARNING]
> DSH **不内置任何索引源**，索引都是第三方提供的。索引里写的插件标题、描述、作者，DSH **不会帮你核实**。只添加你信任的索引源，安装前看清确认框里的来源。

> [!TIP]
> 社区整理的插件列表：[awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)（插件精选清单）。

### 安装插件前检查

和第 13 章检查 skill 类似，再加几条：

- [ ] 插件**最近有没有更新**，支持你现在的 DSH 版本吗？
- [ ] GitHub 上有多少人用（Star 数）、有没有人报告问题（Issues）？
- [ ] 它需要哪些权限？说明里有没有提到会联网、会读取文件？
- [ ] **一次只装一个**。装完用一两天，没问题再装下一个。出了问题，你才知道是哪个插件造成的

## 4. 安全地修改配置文件

第 18 章你已经改过一次 `cordis.patch.yml`。总结一下规矩：

### 这个文件是什么

`cordis.patch.yml` 是**你自己的修改清单**。DSH 启动时，先拼出官方默认的样子，再按这份清单做修改。所以：

- 你在这里写的，会**覆盖**默认设置
- 删掉你写的内容，就**恢复**默认

### 改之前

1. **备份**：复制一份，文件名加上日期
2. **只加不删**：不确定的原有内容，不要删
3. **写注释**：在你加的内容上面，用 `#` 开头写一行说明，比如 `# 第 18 章:Exa 搜索 MCP`。以后自己看得懂

### 改的时候

- **只用空格缩进，不用 Tab**
- 用 VS Code 编辑，有红色波浪线就是格式错了

### 改完之后

- 重启 DSH 生效
- 打不开了 → 用备份恢复

### 让 AI 帮你改？

可以，但要注意：

```
请帮我在 DSH 的配置文件里关掉某某插件。
修改之前先备份原文件,然后把你要修改的内容给我看,我确认后再改。
```

> [!WARNING]
> 不要让 AI 在你没看过的情况下直接改配置文件。

## 6. 常见问题

**问：装了插件后 DSH 打不开了？**
答：如果是通过配置文件加的，用备份恢复；如果是在插件页面装的，打开 DSH 后去「插件」页面关掉或卸载它。实在打不开，可以把那个 profile 的 `cordis.patch.yml` 里相关的内容删掉。

**问：我能自己做插件吗？**
答：能，但需要会写 TypeScript 代码。见 🟡 选修 [第 21 章](21-plugin-dev.md)。

**问：命令行能装插件吗？**
答：可以，用 `dsh plugin --profile <名字> add <插件包名>`。新手建议用界面。
