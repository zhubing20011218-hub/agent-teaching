# 第 12 章 Skill 是什么

> **学完这一章,你能:**
> - 用"说明书"的比喻讲清楚 skill
> - 看懂一个 skill 文件夹里有什么,尤其是最重要的 `description`
> - 分清 skill、AGENTS.md、MCP、插件这四样东西
>
> **前置:** 第 10 章(会用 DSH 干活)

## 1. 为什么要学这个

你可能已经发现:让 AI 做 PPT,每次都要交代一大堆——"用什么字体、颜色别太多、每页别放太多字、做完检查一下有没有文字跑出框外……"

每次都说一遍,很累。说漏了,做出来就不对。

**有没有办法把这些要求写下来,让 AI 需要的时候自己去看?** 有,这就是 **skill**。

## 2. 讲解

### Skill = 放在书架上的说明书

打个比方:AI 是一个聪明的新员工。

- 他什么都懂一点,但**不知道你们公司的具体做法**
- 你把各种工作的做法写成**说明书**,放在他办公桌旁的**书架**上
- 他平时不看。**接到相关工作时,才从书架上拿出对应那本**,照着做

**Skill 就是这样的说明书。** 中文常叫"技能"。

为什么要"用的时候才看",而不是一开始就全部告诉 AI?

- 第 3 章讲过:AI 每次都要把所有内容重新读一遍,**读得越多越花钱**
- 内容太多,AI 也容易"抓不住重点"

所以 DSH 平时只告诉 AI 一份**目录**:"书架上有这些说明书,每本是干什么的"。AI 判断当前工作需要哪本,才把那本的全文拿来看。这叫**按需加载**。

### 一个 skill 长什么样

一个 skill 就是**一个文件夹**,里面至少有一个叫 `SKILL.md` 的文本文件:

```
pptx/                    ← skill 的文件夹,名字就是 skill 的名字
├── SKILL.md             ← 说明书正文(必须有)
├── LICENSE.txt          ← 许可证(谁写的、别人能怎么用)
└── scripts/             ← 附带的小工具(有些 skill 有)
    ├── thumbnail.py
    └── ……
```

`SKILL.md` 分两部分:

```markdown
---
name: pptx
description: 任何涉及 .pptx 文件的工作都用这个 skill:新建演示文稿、
  读取 PPT 内容、修改已有的 PPT……用户提到"幻灯片""演示文稿""PPT"时使用。
---

# PPT 制作和编辑

## 新建 PPT 的步骤
1. 先确定大纲……
2. ……

## 常见的坑
- 不要用 Aptos 字体……
```

- **上半部分**(两条 `---` 之间):叫**头部信息**(专业名称 frontmatter),是给 DSH 看的"标签"
- **下半部分**:**说明书正文**,是给 AI 看的具体做法,就是普通的文字

### 头部信息里有什么

| 字段 | 必须有吗 | 作用 |
|---|---|---|
| `name` | ✅ 必须 | skill 的名字,一般和文件夹名一样 |
| `description` | ✅ 必须 | **最重要的一行**:写清"这本说明书是干什么的、什么时候用" |
| `whenToUse` | 可选 | 补充说明什么时候用 |
| `disable-model-invocation` | 可选 | 设成 `true`:AI 不会自己去用它,只能你手动叫 |
| `user-invocable` | 可选 | 设成 `false`:你不能手动叫它,只有 AI 自己判断时用 |

### 为什么 `description` 最重要

还记得"目录"吗?**AI 平时只能看到每个 skill 的 `name` 和 `description`。** 它完全靠 `description` 来判断"这个工作要不要拿出这本说明书"。

- `description` 写得好:AI 该用时就会用
- 写得含糊:AI 不知道什么时候该用,该用时不用,不该用时乱用

对比一下:

- ❌ `description: PPT 工具`(太短,AI 不知道什么情况下用)
- ✅ `description: 制作、修改、美化 PowerPoint 演示文稿(.pptx)时使用。用户提到"PPT""幻灯片""演示文稿""汇报材料",或者给了一个 .pptx 文件时,都用这个 skill。`

第 17 章自己写 skill 时,会专门练习怎么写 `description`。

### Skill 被用上的两种方式

| 方式 | 怎么触发 | 例子 |
|---|---|---|
| **AI 自己判断** | AI 看了目录,觉得当前工作需要 | 你说"帮我做个 PPT",AI 自己去加载 `pptx` |
| **你手动叫** | 在输入框里输入 `/` 加 skill 名字 | 输入 `/pptx`,直接指定用这个 skill |

skill 被加载时,对话里会出现一行「**加载技能**」的记录,点「查看」可以看到它加载的是哪个 skill(第 13 章会教你怎么确认)。

### 分清四样东西

学 Agent 时,你会经常听到这四个词。用一张表分清它们:

| | 比喻 | 是什么 | AI 什么时候看到 | 本教程哪一章 |
|---|---|---|---|---|
| **AGENTS.md** | 墙上贴的**规章制度** | 写在项目文件夹里的规则文件,比如"本项目回答一律用中文" | **每次都看** | 第 20 章 |
| **Skill** | 书架上的**说明书** | 某类工作的具体做法 | **需要时才看** | 第 12–17 章 |
| **MCP** | 墙上的**万能插座** | 把外部工具(比如搜索引擎、数据库)接给 AI | 接上就能用 | 第 18 章 |
| **插件** | 给管家**换装备** | 给 DSH 本身增加新功能(比如新界面、新工具) | —— | 第 19 章 |

简单记:

- **规则**(每次都要遵守的)→ 写进 AGENTS.md
- **做法**(做某类事的步骤和经验)→ 写成 skill
- **工具**(AI 本来没有的能力)→ 接 MCP 或装插件

> 💡 skill 最适合新手:**它只是一个文本文件**,不用写代码,写的都是普通的话。

### Skill 是通用的

skill 的格式最早来自 Anthropic(做 Claude 的公司),现在 DSH、Claude Code、Codex 等很多工具都支持**同一种格式**。一个 skill 写好,在这几个工具里基本都能用。

所以网上有大量别人写好的 skill,可以直接拿来用(下一章教你怎么装)。

## 3. 跟着做:读懂一个真实的 skill

我们来读一个真实的、官方写的 skill:Anthropic 的 `pptx`(做 PPT 用的)。

1. 打开 https://github.com/anthropics/skills/tree/main/skills/pptx
2. 你会看到三样东西:`LICENSE.txt`、`SKILL.md`、`scripts` 文件夹
3. 点 `SKILL.md`,看最上面两条 `---` 之间的部分

找一找:

- [ ] `name` 是什么?
- [ ] `description` 里提到了哪些"触发词"?(提示:deck、slides、presentation、.pptx……)
- [ ] 正文里有没有提到要用到哪些其他软件?(提示:找找 LibreOffice、pptxgenjs、markitdown)

## 5. 常见问题

**问:skill 和"提示词"有什么区别?**
答:skill 本质上就是一份**写好、存好、需要时自动拿出来用**的提示词,外加可能附带的小工具。普通提示词要你每次自己打。

**问:装了很多 skill,会不会更花钱?**
答:每个 skill 平时只占"目录"里的一两行(名字 + 描述),所以装几十个影响也不大。只有被加载的那个才会把全文发给 AI。但也别装太多用不上的,目录太长 AI 也会挑花眼。

**问:skill 会不会有危险?**
答:**会。** skill 是别人写的说明书,AI 会照着做;有些还带了脚本,会在你电脑上运行。下一章专门讲怎么检查。
