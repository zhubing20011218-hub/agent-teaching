# 写作规范:写给完全没有编程基础的人

> 这份教程的读者是**零基础的新手**:会用电脑、会复制粘贴,但没写过代码、没用过终端。
> 写每一章之前先读一遍这份规范;写完之后用最后的「自查清单」检查一遍。

## 一、说人话

1. **每个新词第一次出现时,先打比方,再用一句大白话解释,最后才给专业名称。**
   - ❌ "API 是应用程序编程接口,用于系统间通信。"
   - ✅ "API 就像餐厅的点菜窗口:你把要求递进去,厨房做好再递出来。专业名称叫 API。"
2. **不用没解释过的英文缩写。** 实在要用,第一次写成「中文(英文)」,比如「工作区(workspace)」。
3. **一句话只说一件事**,尽量不超过 30 个字;一段不超过 4 句。
4. **不写"显然""简单地""众所周知""只需要"。** 对刚入门的读者来说，没有什么是"显然"的。
5. **先说结论,再说原因。** 读者最想知道"我要做什么",然后才是"为什么"。
6. **用读者身边的例子**:做 PPT、整理照片、查资料、写日报,不要用"实现一个排序算法"这种例子。

## 二、操作步骤要"抄着就能做"

1. **每一步编号**,一步只做一个动作。
2. **每一步都写清楚"做完应该看到什么"**,最好配截图。读者看到一样的画面才敢往下走。
3. **命令放在单独的代码框里**,并说明:在哪里输入(终端 / DSH 对话框)、输完要按回车。
4. **告诉读者哪些地方要换成自己的内容**,用「把 `你的文件夹` 换成……」这种写法,并给例子。
5. **Mac 和 Windows 不一样的地方分开写**,不要让读者自己猜。
6. **出错了怎么办**:每章末尾的「常见问题」写出最常见的 3–5 个报错,原样贴出报错文字,再写怎么解决。

## 三、安全提醒要醒目

- 涉及 API 钥匙、密码、付款、删除文件、安装别人的 skill / 插件时,用 `> ⚠️` 提示框单独提醒。
- 截图里的钥匙、邮箱、账号必须打码。
- 不教读者关掉安全提示、跳过审批。

## 四、保持"可持续更新"

- 每章开头的 `verified_with`(验证版本)和 `last_checked`(验证日期)必须填。
- 界面按钮、菜单位置这类容易变的细节,写清楚的同时附上官方文档链接。
- 用到别人仓库的 skill / 工具时,注明仓库链接、许可证;**许可证不允许转载、或者没有许可证的,只放链接,不复制文件。** 引用前以对方仓库**当前**的许可证为准(例如 Anthropic 的 `pptx` skill 早期是专有许可,现在已改为 Apache 2.0)。
- DSH 升级后,把受影响的章节和改动写进附录 C「更新日志」。

## 五、写完自查清单

- [ ] 找一个不懂编程的人(或假装自己是)读一遍:有没有一个词他看不懂?
- [ ] 每个新词都有比喻 + 大白话解释吗?
- [ ] 每一步都写了"应该看到什么"吗?
- [ ] 命令都能直接复制运行吗?要替换的地方标出来了吗?
- [ ] 截图里的敏感信息打码了吗?
- [ ] 填了验证版本和验证日期吗?
