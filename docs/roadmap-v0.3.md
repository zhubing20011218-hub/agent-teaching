### 新第 10 章:厂商渠道和自定义渠道(API 地址讲透)

按 DSH 桌面版 0.2.2-rc.3 的真实界面写,下面的名字已和 DSH 源码核对过:

| DSH 里的叫法 | 俗称 | 要填什么 | API 地址 |
|---|---|---|---|
| DeepSeek 官方(欢迎页「添加 API Key」) | 官方渠道 | 只填钥匙 | 自动,不用填 |
| 「添加模型提供商」→「第三方模型提供商」 | 厂商渠道 | 选厂商 + 填那家的钥匙 | 界面显示「由提供方配置地址」,一般不用填 |
| 「添加模型提供商」→「自定义模型 API」 | 自定义渠道 | Provider ID + **API 地址** + **API 协议** + 钥匙 + 模型 | **必须自己填** |

这一章要讲清楚的细节:
1. **为什么要填地址**:地址就是“把信寄到哪个门牌号”。厂商渠道,DSH 已经知道门牌号;自定义渠道,DSH 不知道,只能你告诉它。
2. **去哪里找地址**:服务商文档或后台里,通常叫 Base URL / 接口地址 / API 地址 / Endpoint。附一张常见服务商地址表,每一行注明核对日期。
3. **最常见的填错**:
   - 结尾要不要带 `/v1`;
   - 不要把完整的 `/chat/completions` 也贴进去;
   - `http` 和 `https` 写错;
   - 多了空格或结尾的斜杠;
   - 协议和地址对不上。比如 DeepSeek 的 OpenAI 格式地址是 `https://api.deepseek.com`,Anthropic 格式是 `https://api.deepseek.com/anthropic`。
4. **四种 API 协议怎么选**:OpenAI Chat Completions / OpenAI Responses / Anthropic Messages / Gemini API。拿不准就选第一种,再问服务商。
5. **模型名**:先点「获取可用模型」;获取不到就手动填,一个字母都不能错。
6. **按报错自查**:401 是钥匙不对,404 是地址路径不对,`model not found` 是模型名不对,连不上多半是网络问题(内网没连、VPN 没开)。
7. 截图位全部用注释标出,由 calmness 补图。

### 新第 11 章:中转站

1. 用“代购”打比方,讲清楚中转站是什么。
2. **单位内部网关**(以学校为真实案例,calmness 连上学校网络后补截图):必须连单位网络或 VPN 才能用;地址常常是内网 IP,比如 `http://10.x.x.x:3000/v1`;用工号或学号登录;额度由管理员分配。说明:它和公开中转站用的往往是同一类软件(new-api、LiteLLM 等),区别只在**搭在哪里、谁能访问**。
3. **公开中转站**:以 `api.prismice.cn`(一个用 New API 搭的站)为例,全流程演示(注册 → 充值 → 建令牌 → 复制地址 → 在 DSH 里填写 → 测试)。**只做演示,不写推荐语、不放推广链接**;文中注明“换成任何同类站,步骤都差不多”。
4. **怎么挑一个靠谱的中转站**:
   - 你的内容会经过它的服务器;
   - 有的会把便宜模型冒充贵模型,教读者用一个简单问题去测;
   - 价格“倍率”要会换算;
   - 先少量充值。
5. 不同角色的提醒:阿芳(会计)的客户数据不走公开中转站;小林(学生)优先用学校提供的网关。

## 四、作品展示区

### 网站上的位置
顶部导航加「**作品展示**」(`/showcase/`),用卡片列出,可以按角色筛选,每张卡片标明难度、大约耗时和大约费用。

### 选项目的标准(全部满足才能进入“精讲”)
1. **公开,且许可证允许**(MIT / Apache / CC 等)。没有许可证的只放链接加点评,不搬代码、不大段引用。
2. **是 AI 做的,而且有证据**:提交记录里有 AI 署名,或者仓库里有 CLAUDE.md / AGENTS.md / 需求文档 / skill 文件。
3. **新手看得懂、做得到**:不需要复杂的服务器,用 DSH 加 DeepSeek 能复刻核心部分。
4. **安全、合规**:不违反平台规则(比如自动海投简历、批量刷号的不要),仓库里也没有泄露的钥匙。

### 拆解模板(每个作品都按这个顺序讲)
1. **一张卡片**:角色、难度、耗时、费用、用到的本事(skill / MCP / 定时任务……)
2. **它解决什么问题**
3. **成品长什么样**(截图位)
4. **作者是怎么一步步做出来的**:从提交记录和项目里的文档还原。**有证据的写“作者是这样做的”,没证据的写“我们推测”,两者分开标注**
5. **用 DSH 复刻一个简化版**:写出每一句对 AI 说的话和操作步骤。**教程制作时不真实调用 API**;文中 AI 的回复统一标注“示例回复,你看到的会不一样”,示例数据按真实场景编写
6. **你来试**:用对应角色的练习素材包
7. **还能怎么改进**

## 八、已确认的决定(2026-11-17)

1. **API 站**:用 `api.prismice.cn` 当公开中转站的演示例子,不做推广;截图由 calmness 以后补。
2. **内部网关**:没有公司的案例,但有**学校的真实案例**;calmness 连上学校网络后补截图。

4. **不用钥匙、不真实调用**:教程里的 AI 回复都标注为示例;示例数据按真实场景编写。
5. **角色**:在 6 个基础上**加一个老师**,共 7 个。
